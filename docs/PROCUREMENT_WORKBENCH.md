# 采购工作台交互

本轮对照用户提供的 rmuc-machining-hub 原项目：static/index.html、static/app.js、backend/bom_parser.py、backend/app.py。参考项目在 C:/Users/lulu/.gemini/antigravity/scratch/rmuc-machining-hub，原项目只读取，未修改。

## 查看与定位

采购入口改为工作台。左侧按申请日期展开，再选择提交人；中间切换零件明细与申请批次，支持姓名、状态、工艺、关键词、日期范围、仅我的筛选；右侧就地显示零件模型、规格、数量、申请人、批次及处理申请操作。

日期按北京时间的申请创建日期归档。后续审核、下单、收货和入库不会把申请移动到操作发生的日期。批次标题默认带当天日期，可改为项目交付批次名称。

明细每页 100 行；支持全选本页与选择当前筛选的全部结果（最多 1000 项），可跨页选择。右侧 STEP 预览沿用现有查看器与螺纹面标注，完整申请与操作记录仍可打开。

批量审核明确以整张申请为单位：确认时显示所选明细涉及几张申请。权限与状态由原申请操作接口重新校验。

## 批量申请

入口：采购工作区“批量申请”，或工作台“批量申请 / 导入 BOM”。

- BOM.zip：读取总表或 BOM 表格，按对应交付文件、编号和名称寻找模型；保留目录工艺类别；同目录同名 STEP/STP 和 DWG 配成一项。
- Excel .xlsx：优先读取“总表”，兼容原项目的编号、零件名称、类别、规格 / 尺寸（mm）、数量、对应交付文件、建议制造 / 采购材料等表头。
- CSV、TSV、Excel 区域粘贴：支持整表导入、中文列名、带引号和换行的单元格、人民币单价转换为整数分。
- 多文件和文件夹：一次选择多个 STEP / DWG，按相对目录配对；可补充已导入 BOM 的交付文件。上传并发为 3，列表不会为每个文件重新绘制一次全部行。
- 标准件带 STEP 参考模型时仍为标准件；仅有 DWG 的加工件可提交及下载，需要三维预览时补充 STEP。

导入后先展示待提交清单。可直接编辑名称、工艺、数量、规格、材料、预算单价和购买链接；勾选多行统一修改工艺或数量，也可移除多行。上传到暂存区不会自动创建或提交采购申请。

填写一次批次标题与小组后，可整批保存草稿、提交组长审核，或并入购物车。每次最多 1000 个明细，整包上限 128 MiB，单个交付附件上限 64 MiB。已有“申请→组长审核→采购下单→申请人确认到货→库管入库”流程继续使用。

## 选中导出

按勾选明细导出 ZIP，内含 BOM.csv 与对应原始 STEP/DWG，目录按申请日期、提交人、批次、工艺组织。BOM.csv 可由 Excel 打开。本轮支持 XLSX 导入，导出的清单格式为 CSV。

## 接口

| 接口 | 用途 |
| --- | --- |
| GET /api/procurement/workbench | 返回可见申请、分页明细、日期/提交人目录与工艺计数。参数 q、state、date、from、to、applicant、category、mine、offset、limit。 |
| POST /api/procurement/imports?name=BOM.zip | 原始文件字节导入，返回待确认明细、附件 ID 与配对提示，不直接创建申请。 |
| POST /api/procurement/imports?format=paste | JSON {text}，解析粘贴表格。 |
| POST /api/procurement/export | JSON {itemIds}，仅导出当前账号可访问的明细与附件。 |

新工作台、目录统计及导出共用原申请可见性规则。飞书登录、团队角色、申请操作、库存事务及飞书同步配置继续由原后端负责。
